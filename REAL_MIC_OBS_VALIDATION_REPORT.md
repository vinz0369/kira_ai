## Measurement contract

The current `voice_end_to_first_playback_ack_ms` clock starts when the **backend receives** the browser VAD-end event and stops when the overlay's Web Audio player sends its playback-start ACK. It is a browser scheduling/ACK proxy for microphone turn-end to browser playback, not a timestamp from the mic hardware, an independently captured first audible sample, or OBS output. Network transit before server receipt and audio-device/OBS mixer latency are not included. P50/P95 must only be computed from actual Voice Real traces with real providers, a connected overlay, and no degraded fallback; report sample count.

OBS-audible latency needs independent recording/timestamp analysis or a human-observed result and must be labeled separately. The operator should not check a manual item merely because an automated ACK exists.
